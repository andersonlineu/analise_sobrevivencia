Guia Prático: Como Interpretar a Saída de summary(coxph()) no R

Um roteiro de leitura do Modelo de Riscos Proporcionais de Cox para pesquisadores

1 Introdução: o que é o modelo de Cox?

A função coxph(), do pacote survival do R, ajusta o Modelo de Riscos Proporcionais de Cox — o modelo de regressão mais utilizado em análise de sobrevivência. Ele modela o efeito de covariáveis sobre a função de risco (hazard) de um indivíduo:

\[\lambda(t \mid \mathbf{x}) = \lambda_0(t) \exp(x_1\beta_1 + x_2\beta_2 + \dots + x_p\beta_p)\]

Três ideias sustentam esse modelo e ajudam a entender por que ele é chamado de semiparamétrico:

  • \(\lambda_0(t)\) é o risco basal — não se assume nenhuma distribuição estatística para ele ao longo do tempo (parte não paramétrica).
  • As covariáveis entram de forma multiplicativa sobre o risco basal — essa é a parte paramétrica do modelo.
  • Pressuposto central: a razão de riscos entre dois indivíduos não varia ao longo do tempo — por isso o nome “riscos proporcionais”. Este pressuposto deve sempre ser verificado (gráficos de Kaplan-Meier estratificados, resíduos de Schoenfeld — ver capítulo sobre análise de resíduos).

Os coeficientes \(\beta\) são estimados por verossimilhança parcial, um método que, a cada tempo de evento, usa apenas a informação dos indivíduos ainda sob risco naquele momento — de forma semelhante à lógica do estimador de Kaplan-Meier.

1.1 Como o R organiza o tempo de sobrevivência

Antes de ajustar o modelo, o R precisa de um objeto que combine, em uma única variável, o tempo de acompanhamento e o indicador de evento. Isso é feito com a função Surv():

library(survival)

tmo <- read.table("tmoclas.dat", header = TRUE)
tmo$sexo <- factor(tmo$sexo)

y <- Surv(tmo$os, tmo$status)
AvisoAtenção a um erro comum de leitura

A primeira variável dentro de Surv() é o TEMPO, não o evento. No exemplo acima, os é o tempo (em dias) até o óbito ou até a censura, e status é o indicador de evento (1 = óbito, 0 = censura). O evento em si nunca é a variável de tempo — é sempre a variável binária de status.

2.1 Cabeçalho (Call:)

O R apenas repete o comando que gerou o modelo — útil para conferir se a fórmula e o banco de dados usados foram realmente os pretendidos.

2.2 Amostra e eventos

n= 96, number of events= 49
  • n: número total de observações (pacientes) que entraram efetivamente no modelo.
  • number of events: quantas dessas observações tiveram o evento observado (ex.: óbito). As demais foram censuradas.
DicaRecomendação

Sempre confira esse número primeiro. Se n for menor que o total de linhas do banco de dados, é sinal de que o R removeu automaticamente observações com valores faltantes (NA) em alguma covariável — o que pode comprometer a comparação entre modelos aninhados com conjuntos de variáveis diferentes (ver Seção 7).

3 Interpretando o Hazard Ratio (HR)

O HR = exp(coef) é a informação mais importante da tabela de coeficientes. Ele expressa a razão entre o risco instantâneo de dois indivíduos que diferem em uma unidade na covariável, mantendo as demais fixas.

Valor do HR Interpretação
HR = 1 Nenhum efeito da covariável sobre o risco (valor de nulidade)
HR > 1 Fator de risco — a covariável aumenta o risco do evento
HR < 1 Fator de proteção — a covariável reduz o risco do evento

Applied Survival Analysis (Hosmer, Lemeshow & May) traz um exemplo clássico: em um estudo com HR = 1,74 para sexo (feminino vs. masculino), a interpretação correta é que mulheres morrem a uma taxa cerca de 1,74 vezes maior que a dos homens ao longo do período de estudo. Uma forma alternativa — e, segundo os autores, muitas vezes mais compreensível — é expressar o HR como percentual de mudança em relação ao valor de nulidade (1):

“a taxa de óbito entre mulheres é 74% maior do que entre homens” (em vez de “1,74 vezes maior”)

A mesma lógica se aplica a efeitos protetores (HR < 1) — os autores destacam que pesquisadores costumam ter mais dificuldade para interpretar esse caso. Um HR = 0,505, por exemplo, pode ser lido de duas formas equivalentes:

  • “A taxa de progressão da doença no grupo tratado é 0,505 vezes a do grupo controle”; ou
  • “A taxa de progressão da doença no grupo tratado é 49,5% menor do que no grupo controle”.

3.1 Traduzindo o exemplo do curso

idade: HR = 0,9786. Como o HR é menor que 1, a idade atua como um discreto fator de proteção neste modelo — a cada ano de idade a mais, o risco de óbito é multiplicado por 0,9786 (redução de ~2,1%). Porém, z = -1,548 e p = 0,122 (acima de 0,05) — não há evidência estatística suficiente de que esse efeito exista de fato na população.

sexo2: HR = 0,6863, também menor que 1, sugerindo ~31% menos risco no grupo “sexo2” em relação à categoria de referência. Mas z = -1,172 e p = 0,241 — não significativo.

Nota

O R nomeia a linha sexo2 porque sexo foi transformado em factor(). O R sempre usa o primeiro nível como categoria de referência e cria uma linha para cada nível seguinte. Para saber qual nível é a referência, use levels(tmo$sexo).

4 Os três testes de significância

O R reporta três testes diferentes para avaliar a significância de coeficientes e de modelos. Todos testam, em essência, a mesma hipótese nula, mas usam abordagens matemáticas distintas — e podem, em amostras pequenas, apontar conclusões ligeiramente diferentes.

4.1 Teste de Wald

Usado para cada coeficiente individualmente (coluna z / Pr(>|z|)):

\[H_0: \beta_j = 0 \qquad z = \hat\beta_j / ep(\hat\beta_j)\]

É simplesmente o coeficiente dividido pelo seu erro-padrão. Quanto mais distante de zero, mais improvável é que o verdadeiro efeito seja nulo. Alguns pacotes (como o SAS) reportam o quadrado dessa estatística, que segue distribuição qui-quadrado com 1 grau de liberdade — resultado equivalente.

4.2 Teste da Razão de Verossimilhança (Likelihood Ratio Test)

Compara o modelo ajustado com um modelo reduzido (ou nulo):

\[H_0: Mod_{maior} = Mod_{menor} \qquad RV = 2(l_{maior} - l_{menor}) \sim \chi^2_{(l-k)}\]

É o teste recomendado para comparar modelos aninhados (ver Seção 7), e costuma ser mais robusto que o teste de Wald quando o número de observações é pequeno. Em amostras grandes, os dois testes tendem a convergir para resultados assintoticamente equivalentes.

4.3 Teste de Escore (Score / log-rank test)

Baseado na derivada da log-verossimilhança parcial avaliada em \(\beta = 0\). Também segue distribuição normal padrão sob a hipótese nula. Quando o modelo tem apenas uma covariável categórica, esse teste coincide com o teste log-rank já conhecido da análise não paramétrica (Kaplan-Meier).

DicaQuando os três testes divergem

É comum, especialmente perto do limiar de significância (p ≈ 0,05), que os três testes apontem conclusões ligeiramente diferentes. A recomendação de Hosmer, Lemeshow e May é reportar todos os resultados obtidos, permitindo que o leitor avalie as diferentes conclusões dentro do contexto de seus próprios objetivos de pesquisa.

5 Intervalo de confiança e o valor de nulidade

Para o hazard ratio, o valor de nulidade é sempre 1 — porque HR = 1 significa nenhuma diferença de risco entre os grupos comparados. As hipóteses do teste são:

\[H_0: HR = 1 \text{ (sem efeito)} \qquad H_1: HR \ne 1 \text{ (há efeito)}\]

ImportanteRegra prática

Se o intervalo de confiança de 95% do HR não contém o valor 1, rejeita-se \(H_0\) com 95% de confiança — equivalente a p < 0,05 no teste de Wald. Se o intervalo contém o 1, a variável não é considerada significativa.

No exemplo do curso, os intervalos de idade (0,9521 – 1,006) e sexo2 (0,3657 – 1,288) contêm o valor 1 — coerente com os p-valores de 0,122 e 0,241 vistos anteriormente. São duas formas diferentes de chegar exatamente à mesma conclusão.

6 Concordância: avaliando o poder discriminatório do modelo

A concordância é uma medida global de ajuste usada quando o objetivo do modelo é predizer risco. Ela avalia a capacidade do modelo de ordenar corretamente os indivíduos por risco — de forma análoga à área sob a curva ROC (AUC) em regressão logística.

Concordância (c) Poder discriminatório
0,3 < c < 0,4 Baixo
c = 0,5 Equivalente ao acaso
0,6 ≤ c < 0,7 Comum
0,7 ≤ c < 0,8 Muito bom
0,8 ≤ c < 0,9 Excelente

No exemplo do curso, c = 0,568 está bem próximo de 0,5 (chute aleatório) — o poder discriminatório do modelo é fraco.

7 Comparando modelos aninhados

Para decidir se novas covariáveis melhoram significativamente o modelo, usa-se o teste da razão de verossimilhança entre modelos aninhados, via anova():

mod2 <- coxph(y ~ idade + sexo + fase, data = tmo)
mod3 <- coxph(y ~ idade + sexo + fase + deag, data = tmo)
mod4 <- coxph(y ~ idade + sexo + fase + deag + decr, data = tmo)

anova(mod1, mod2, mod3, mod4, test = "Chisq")

Cuidados importantes ao usar essa comparação:

  • Os modelos precisam ser aninhados (um contido no outro) e ajustados sobre o mesmo conjunto de observações (mesmo n).
  • Não é possível comparar diretamente modelos estratificados com modelos não estratificados.
  • Se houver valores faltantes em alguma covariável, os modelos podem perder comparabilidade — use complete.cases() para garantir que todos sejam ajustados sobre exatamente as mesmas observações.
  • Em amostras pequenas, a análise pela função desvio (razão de verossimilhança) tende a ser mais robusta do que o teste de Wald equivalente.

8 Roteiro rápido de leitura

Para qualquer saída de summary(coxph(...)), siga esta sequência:

  1. Confirme n e number of events — a amostra está completa, sem perda inesperada de observações?
  2. Para cada covariável, leia exp(coef) — é o hazard ratio: acima de 1 indica risco, abaixo de 1 indica proteção.
  3. Verifique a significância pelo teste de Wald (z / Pr(>|z|)) ou pelo intervalo de confiança de 95% do HR — lembrando que o valor de nulidade é 1.
  4. Avalie a Concordância, usando a tabela de referência acima, para julgar o poder discriminatório do modelo.
  5. Observe os testes globais (razão de verossimilhança, Wald, escore/log-rank) — o modelo completo é melhor do que o modelo nulo?
  6. Ao comparar modelos aninhados, use anova(..., test = "Chisq") — e confirme que todos foram ajustados sobre o mesmo n.
  7. Antes de reportar os resultados, verifique o pressuposto de riscos proporcionais (resíduos de Schoenfeld).
